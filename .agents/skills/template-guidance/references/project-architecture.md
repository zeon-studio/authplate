# Project Architecture

This skill provides a high-level map of the Authplate template ecosystem, built on Next.js 16+ App Router, Better Auth, Prisma, and Tailwind CSS v4.

## High-Level Folder Structure

**Important for AI Agents:** The exact subdirectories may vary. **Always list the root directory and `src/` to understand the specific structure of the current fork.**

Common architecture examples include:

```text
├── .agents/skills/    # AI Agent skills (like this document)
├── prisma/            # Prisma schema and migrations
├── public/            # Static assets (images, fonts, favicon)
├── scripts/           # Node scripts (JSON generation, dark mode removal)
├── src/
│   ├── app/           # Next.js App Router pages, layouts, and route groups
│   │   ├── (auth)/        # Auth pages (signin, signup, forgot-password)
│   │   ├── (dashboard)/   # Protected dashboard pages (settings, billing, subscriptions)
│   │   ├── (protected)/   # Other protected pages (e.g., pricing checkout)
│   │   ├── [regular]/     # Catch-all for markdown-driven pages
│   │   ├── actions/       # Server Actions (user, OTP, payments, email sender)
│   │   └── api/           # API routes (auth catch-all, payment webhooks)
│   ├── config/        # Global JSON/TS configuration files
│   ├── content/       # Markdown/MDX content database
│   ├── generated/     # Prisma generated client (auto-generated, DO NOT EDIT)
│   ├── hooks/         # Custom React hooks
│   ├── layouts/       # Reusable UI Components, Partials, and shadcn/ui
│   ├── lib/           # Auth config, Prisma client, validation schemas, utilities
│   ├── styles/        # Tailwind v4 CSS configuration and custom styles
│   └── types/         # TypeScript definitions
```

## Data Flow: From Content to Page

This template functions as a Git-based CMS for public pages. Here is how data moves through the system:

1. **Content Definition**: A user creates `src/content/blog/my-post.md`.
2. **Data Parsing**: Functions inside `src/lib/` (e.g., `getSinglePage`, `getRegularPage`) are called by Next.js Server Components. These functions read the file system, parse the frontmatter using `gray-matter`, and return structured JSON.
3. **Routing**: The `src/app/blog/[single]/page.tsx` dynamic route catches the URL `/blog/my-post`.
4. **Rendering**: The page component receives the parsed markdown data, renders the HTML using `next-mdx-remote` or `marked`, and wraps it in UI components from `src/layouts/`.

## Auth & Protected Data Flow

For authenticated pages, the flow is different:

1. **Auth Config**: `src/lib/auth/auth.ts` defines the Better Auth server instance with Prisma adapter, plugins, and social providers.
2. **API Handler**: `src/app/api/auth/[...all]/route.ts` exposes all Better Auth endpoints as a Next.js catch-all route.
3. **Client Usage**: `src/lib/auth/auth-client.ts` exports client-side hooks (`useSession`, `signIn`, `signOut`, etc.) for React components.
4. **Server Usage**: `src/lib/auth/auth-server.ts` exports `getServerAuth()` for Server Components and layouts.
5. **Route Protection**: Dashboard layout (`src/app/(dashboard)/layout.tsx`) calls `getServerAuth()` and redirects unauthenticated users.
6. **Database**: Prisma with PostgreSQL stores users, sessions, accounts, subscriptions, and payments.

## What to Edit vs. What to NEVER Touch

### ✅ Safe to Edit
- **`src/content/**`**: Where all text and image content lives.
- **`src/config/**`**: Where global settings, menus, and social links are defined.
- **`src/app/**`**: Add new routes or modify page templates here.
- **`src/layouts/**`**: Modify or add UI components.
- **`src/styles/theme.css`**: Where color variables for light and dark mode are defined.
- **`src/lib/auth/auth.ts`**: Where Better Auth is configured (plugins, providers, hooks, etc.).
- **`prisma/schema.prisma`**: Where the database schema is defined (run `pnpm db:migrate` after changes).
- **`src/lib/validation/**`**: Where Zod validation schemas are defined.

### 🚫 NEVER Touch (Without Extreme Caution)
- **`src/generated/**`**: Auto-generated by Prisma. Run `pnpm db:generate` instead of editing.
- **`src/styles/variables.css`**: Maps raw CSS variables from `theme.css` to Tailwind's `@theme` tokens and shadcn/ui semantic tokens. Only edit if adding new design tokens.
- **`src/lib/` markdown parsers**: Unless you are deliberately changing the core mechanics of how `.md` files are read, leave these alone. They are highly dependent on the exact folder structure in `src/content/`.
- **`scripts/`**: The build and dev scripts. Modifying `jsonGenerator.mjs` can break content generation.

## Build Pipeline Architecture

When `pnpm dev` or `pnpm build` is executed:
1. `next dev` / `next build` → The standard Next.js process (no pre-build scripts are run automatically).
2. `pnpm generate-json` → Runs `node scripts/jsonGenerator.js` to generate content indexes when needed.

### Database Commands
- `pnpm db:generate` → Generates the Prisma client into `src/generated/prisma/`.
- `pnpm db:push` → Pushes schema changes to the database (for prototyping).
- `pnpm db:migrate` → Creates and applies a migration (for production-ready changes).
- `pnpm db:studio` → Opens the Prisma Studio GUI for database inspection.
